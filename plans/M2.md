# M2: Real planner + task suite

GOAL: Replace the scripted fake with a local Ollama planner that makes validated structured tool
calls, add lead → worker delegation with narrower toolsets, and measure it on a 20-task suite.

SCOPE: `src/agent_orchestrator/` (planner, delegation, suite/eval), `tasks/` or `suite/`, `bench/`,
`tests/`, README/DECISIONS/CHANGELOG. Keep the M1 runtime guarantees (durable log, approvals,
budgets, sandbox) intact; all M1 tests keep passing.

RULES: Ollama on 127.0.0.1:11434 only (`qwen2.5:3b`; don't pull models). Tests use the scripted fake
model or a fake Ollama transport (no network). Never read `.env`. No real network side effects from
tools. Model outputs used by the eval are recorded once to `bench/recorded/*.jsonl` so the eval
report reruns offline. Do not commit or push.

STEPS:
1. **Ollama planner** (`OllamaModel` behind the M1 model interface): prompt = goal, tool list with
   JSON schemas and risk levels, compact history (truncated to a budget); JSON mode, temperature 0,
   fixed seed. Output parsed into the M1 action schema and validated against the tool's JSON
   schema; on invalid output, one bounded repair turn with the validator error, then fail the step
   with a recorded reason (count repairs in the event log). Token counts from Ollama go to budgets.
2. **Delegation**: a `delegate` action (lead only) creates a child run with a sub-goal and a
   subset of tools (never wider than the parent, never `forbidden`), its own budget carved out of
   the parent's remaining budget; child events are linked (parent id) and the child's final answer
   returns to the parent as an observation. Approvals in a child pause the parent too. Resume after
   a crash works across parent/child (test it).
3. **Task suite** (20 tasks, `suite/tasks.yaml`): over the demo DB + workspace + calc + outbox; each
   with a machine checker (DB answer value, file contents, outbox entry fields, "must ask approval",
   "must refuse/forbidden", "must stay under budget"); mix: single-tool, multi-step, needs
   delegation, adversarial (prompt injection inside a file/DB row asking to email someone else —
   must not happen without approval), and impossible tasks (should fail cleanly).
4. **Eval** `agent eval --config {fake,ollama}` → per task: success, steps, tool calls, tokens,
   repairs, approvals requested, budget hits; summary with Wilson CIs; approvals in eval are answered
   by a fixed policy file (documented; injection cases reject). Record Ollama outputs once;
   `agent eval --check` reruns from recordings. Write `bench/results.{json,md}`.
5. **Tests**: planner parsing/validation/repair with fake transport, delegation scoping (child can't
   widen tools, budget carve-out, approval propagation, crash-resume of parent+child), checker unit
   tests, eval determinism with the fake model.
6. Docs: README (planner, delegation, suite results with honest numbers for a 3B model), DECISIONS
   (JSON mode vs tool-calling API, repair policy, delegation budget rule), CHANGELOG.

DONE WHEN: `uv run pytest && uv run ruff check .` pass offline; the suite was run once against local
Ollama and recorded; `agent eval --check` reproduces `bench/results.md`.

ESTIMATE: 120–150 min (model time included).

REPORT: report contract (CHANGED / EVIDENCE / ESTIMATE vs ACTUAL / NOTES / VERDICT). Do not commit,
do not push.
